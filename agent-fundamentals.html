راهنمای مفاهیم پایه

AI Agent را از پایه درست بفهمیم

Token، context window، prompt، tool و hook چه هستند و چطور کنار هم یک Agent قابل‌اعتماد می‌سازند؟

مدل را مثل یک همکار با حافظهٔ محدود تصور کن: باید ورودی را خوب بسته‌بندی کنی، ابزار مناسب را در اختیارش بگذاری و لحظه‌های مهم را با hook کنترل کنی.

واژه‌نامهٔ سریع

هفت قطعهٔ اصلی یک Agent

Token

input unit

واحدهای کوچک متن که مدل می‌خواند و تولید می‌کند؛ همیشه برابر با یک کلمه نیستند.

Text is measured in tokens, not just words.

Context window

working memory

حداکثر tokenهایی که مدل می‌تواند در یک درخواست ببیند؛ ورودی و خروجی هر دو حساب می‌شوند.

Context = instructions + history + retrieved data + output.

Prompt

instructions

دستور، زمینه و قالب خروجی که رفتار مدل را برای یک کار مشخص هدایت می‌کند.

A good prompt makes the job and constraints explicit.

Tool

action

تابعی بیرون از مدل؛ مثل جست‌وجو، خواندن فایل یا ثبت سفارش که Agent می‌تواند آن را صدا بزند.

Tools let a model act beyond text generation.

Hook

lifecycle event

نقطهٔ قابل‌کنترل در چرخهٔ اجرا؛ مثلاً قبل از فراخوانی ابزار یا بعد از دریافت پاسخ.

Hooks are ideal for logging, validation, and safety checks.

Memory

persistence

اطلاعاتی که بین درخواست‌ها نگه داشته می‌شود؛ context window با memory یکی نیست.

Memory persists; context is the current working space.

Skill

reusable ability

یک توانایی تخصصی و قابل‌استفادهٔ مجدد که می‌تواند بخشی از چند workflow باشد.

Skills package repeatable expertise.

این قطعه‌ها چطور کنار هم کار می‌کنند؟

یک چرخهٔ سادهٔ اجرای Agent

Promptهدف و محدودیت
←
Modelتصمیم بعدی
←
Toolاقدام بیرونی
←
Hookبررسی و ثبت
←
Responseنتیجهٔ قابل‌فهم

مثال: hook قبل از tool call می‌تواند جلوی ارسال دادهٔ حساس را بگیرد.

beforeToolCall(context) { if (containsSecret(context.arguments)) { return { allow: false, reason: "redact secrets first" }; } return { allow: true }; }

سه مثال تمیز و کاربردی

از مفهوم تا طراحی واقعی

01دستیار پشتیبانی

مدل پاسخ را می‌سازد، tool وضعیت سفارش را می‌خواند و hook قبل از پاسخ، اطلاعات شخصی را ماسک می‌کند.

prompt → getOrderStatus() → redactPII() → response

02تحلیل‌گر گزارش خطا

Workflow مراحل را مشخص می‌کند؛ skillهای تحلیل log، خلاصه‌سازی و ارسال گزارش هرکدام یک کار تخصصی انجام می‌دهند.

receive → analyze-log → summarize → send-report

03Agent با حافظه

ترجیحات کاربر در memory ذخیره می‌شود، اما فقط اطلاعات لازم برای همین گفت‌وگو وارد context window می‌شود.

memory.store(preference) context = retrieve(relevantOnly=true)

04Prompt خوب در برابر Prompt مبهم

به‌جای «این را بررسی کن»، نقش، ورودی، معیار موفقیت و قالب خروجی را مشخص کن.

Return JSON: {severity, cause, next_step} Use only the supplied logs.
